# API для веб-помощника «Колибри»

Фронтенд работает на Angular. Для локального показа используется Express, для рабочего сайта — FastAPI и PostgreSQL. В разделе «Сценарии» сотрудники создают темы и назначают их инструкциям. На сайте после выбора роли открываются темы, затем опубликованные сценарии выбранной темы и роли.

## Новые эндпоинты

| Метод и путь | Что принимает и возвращает |
| --- | --- |
| `GET /api/instructions?audience=self&topic_id=3` | Список опубликованных инструкций. Фильтры можно опустить. Элемент содержит `id`, `title`, `description`, `audience`, URL озвучки `title_audio_url` и `description_audio_url`, а также `image_url` первого шага, если оно задано. Пустой список возвращается как `[]`. |
| `GET /api/instructions/{id}` | Полная опубликованная инструкция с шагами. Для отсутствующей или снятой с публикации — `404`. |
| `GET /api/instruction-topics?audience=self` | Темы с опубликованными сценариями указанной аудитории. Без фильтра — темы для всех ролей. Элемент содержит `id`, `title`, `description`. |
| `GET /api/admin/instruction-topics` | Все темы, в том числе пока пустые. |
| `POST /api/admin/instruction-topics` | Создаёт тему из `title` и `description`. Возвращает тему и `201`. Совпадающее название — `409`. |
| `POST /api/admin/instruction-media` | Загружает исходные байты изображения или аудио с соответствующим `Content-Type`. Лимит демо — 8 МБ. Ответ `201` с `{ "url": "/api/instruction-media/<id>.<ext>" }`. |
| `GET /api/instruction-media/{filename}` | Отдаёт загруженное медиа для шага или ответа. |
| `GET /api/admin/instructions` | Полные данные всех инструкций, включая черновики. Можно передать `audience`. |
| `GET /api/admin/instructions/{id}` | Полные данные одной инструкции, включая черновик. |
| `POST /api/admin/instructions` | Создаёт черновик или сразу публикует сценарий. Возвращает сохранённый объект и `201`. |
| `PUT /api/admin/instructions/{id}` | Заменяет граф и данные инструкции целиком. Через `is_published` редактор публикует или снимает инструкцию с сайта. Возвращает сохранённый объект и `200`. |
| `DELETE /api/admin/instructions/{id}` | Удаляет сценарий. Возвращает `204`. |
| `GET /api/admin/pictograms` | Возвращает справочник `pictograms` (у каждой записи `id`, `title`, `category`, `url` и `aliases`), наборы `sets` с полями `id`, `title`, `pictogram_ids` и общую для редактора `selection`. |
| `PUT /api/admin/pictograms` | Сохраняет и возвращает `selection` вида `{ "set_id": "arasaac-all", "pictogram_ids": ["arasaac-2467"] }`. Несуществующий набор, повторы и пиктограммы из другого набора дают `422`. Пустая подборка допустима. |
| `POST /api/admin/pictograms/import` | Добавляет набор из JSON и возвращает `{ "set": { ... }, "pictograms": [ ... ] }`. `201` означает создание, `200` — повтор того же импорта, `409` — совпадение имени с другим набором. |
| `GET /api/pictogram-images/{id}` | Отдаёт изображение загруженной пиктограммы. URL сохраняется в сценарии и доступен с публичной страницы. |
| `POST /api/callback-requests` | Принимает заявку на обратный звонок. Возвращает `{ "id": 42, "status": "received" }` после сохранения. |
| `GET /api/admin/callback-requests` | Список обращений для сотрудников. Заглушка отдаёт `id`, `phone`, `created_at`, `status`. Публичная часть этот список не запрашивает. |
| `GET /api/site-display` | Возвращает список ролей и параметры кнопок пожертвований и волонтёрства. |
| `PUT /api/admin/site-display` | Сохраняет названия, описания и озвучку ролей, подписи кнопок, адреса и выбранные для каждой кнопки роли. |
| `PATCH /api/admin/requests/{id}` | Выполняет действие `clarify`, `accept`, `complete`, `cancel` или `restore`, сохраняет `details` в ожидании встречи или назначает сотрудника через `specialist_id`. Поддерживает прежние поля `status` и `take`. |
| `GET /api/admin/requests/{id}/history` | Показывает хронологию статусов и назначений с датой и временем, автором и назначенным сотрудником. |

Для административных маршрутов используется действующая авторизация `Authorization: Bearer <token>`. Публичные запросы не требуют учётной записи. Ошибка содержит `detail`. Для невалидных данных возвращайте `422`, для отсутствующего объекта — `404`, для запроса без сессии сотрудника — `401`.

## Данные инструкции

Тело `POST` и `PUT` выглядит так.

```json
{
  "title": "Покупка продуктов",
  "title_audio_url": null,
  "description_audio_url": null,
  "description": "Как сделать покупки в магазине",
  "audience": "self",
  "topic_id": 3,
  "is_published": true,
  "start_step_id": "take-basket",
  "steps": [
    {
      "id": "take-basket",
      "title": "Возьмите корзину",
      "body": "Найдите корзину у входа.",
      "image_url": "/kolibri/shop-1.jpg",
      "audio_url": null,
      "title_audio_url": null,
      "next_id": null,
      "choices": []
    }
  ]
}
```

В сохранённый объект API добавляет числовой `id` и даты `created_at`, `updated_at` в ISO 8601. Аудитория задаётся ключом из `roles` в `/api/site-display`. Переименование роли сохраняет её ключ и связи со сценариями. Идентификаторы шагов и ответов передаёт редактор. Вариант ответа имеет поля `id`, `label`, `next_id` и необязательные `image_url`, `audio_url`. Если ответы есть, маршрут определяет выбранный ответ. На шаге без ответов маршрут определяет `next_id` самого шага. Значение `null` ведёт к завершению.

Каталог включает `kolibri-all` и `arasaac-all`. Прежние подборки `everyday` и `health` переносятся в `kolibri-all`. Выбор всех элементов `arasaac-basic` расширяется до полного каталога, а частичный выбор сохраняется в `arasaac-all`. URL, назначенные шагам и ответам, сохраняются при смене набора.

Индекс `shared/pictograms/arasaac-index.json` собран из открытых каталогов `https://api.arasaac.org/v1/pictograms/all/ru` и `https://api.arasaac.org/v1/pictograms/all/es`. Для обновления встроенного индекса загрузите оба JSON и выполните `node demo/import-arasaac.mjs ru.json es.json` из `frontend`. Изображения каталога загружаются по ссылкам `https://static.arasaac.org/pictograms/{id}/{id}_300.png`. Ранее добавленные изображения доступны по прежним локальным ссылкам.

Для загрузки пользовательского набора в уже работающую админ-панель используйте файл JSON или ручную форму во вкладке «Пиктограммы». Тело запроса содержит `version: 1`, `title` и массив `pictograms` из объектов с `title`, `category`, `aliases` и `image`. Поле `image` содержит `mime_type` и `base64`. Допустимы PNG, JPEG и WebP до 512 КиБ на файл, до 250 файлов и 16 МиБ на запрос. «Сохранить подборку» применяет выбранный набор в редакторе. В FastAPI данные и изображения хранятся в PostgreSQL. При первом подключении выполните `alembic upgrade head` и примените ограничение для маршрута импорта из `deploy/nginx/twc.conf.example`.

- PostgreSQL хранит темы, сценарии и граф шагов. Поле `topic_id` связывает сценарий с существующей темой. Граф сохраняется вместе со сценарием одной транзакцией. Опубликованное изменение сразу появляется в публичных запросах. Для этих маршрутов выполните `alembic upgrade head`. Лимит nginx на загрузку озвучки и изображений указан в `deploy/nginx/twc.conf.example`.
- Разрешить сохранять незаконченный черновик. При публикации проверить название, первый шаг, заголовки и подписи ответов. Отклонять повторяющиеся идентификаторы, переходы на отсутствующий шаг, недостижимые шаги и шаги, из которых невозможно завершить инструкцию. Цикл с выходом допустим. По возможности передавать идентификатор проблемного шага или ответа вместе с причиной.
- Заглушка проверяет до 100 шагов и до 20 ответов на шаг. Ограничения редактора — 120 символов для названия, 500 для описания, 160 для заголовка шага или ответа, 4000 для текста шага и 2048 для ссылки.
- Медиа хранятся локально в демо и в PostgreSQL в рабочем API. Лимит на файл — 8 МБ. Озвучка заголовка шага хранится в `step.title_audio_url`, текста — в `step.audio_url`, ответа — в `choice.audio_url`. Если у фрагмента нет записи, его озвучивает браузер. Старые совмещённые записи используют необязательное `step.audio_body_start` — долю длительности, с которой начинается текст после названия. Если текст у старого шага пуст, его `audio_url` применяется к названию.

## Слоты и календарь сотрудников

- `POST /api/admin/slots` принимает обязательный `specialist_id` действующего сотрудника вместе с `starts_at`, `ends_at` и `is_open`. `PATCH /api/admin/slots/{id}` с `specialist_id` назначает сотрудника на старый слот. Если слот уже назначен и занят, изменение возвращает `409`. Для одного специалиста слоты не должны пересекаться. Проверка должна работать при одновременных запросах.
- `GET /api/slots`, `GET /api/admin/slots` и вложенный `slot` в заявке возвращают `specialist_id` и `specialist_name`. Старые слоты без назначения должны оставаться доступны для ручной привязки. Заявки вне слота остаются в общем списке.
- `GET /api/admin/requests?scope=mine&status=confirmed` фильтрует записи по специалисту текущей сессии. `status` можно опустить. Без `scope=mine` действует общий список сотрудников.
- Заявка со слотом получает специалиста этого слота при создании. После этого назначение сотрудника хранится в самой заявке. Смена статуса и назначение фиксируются с автором и временем. Миграция старых заявок переносит дату создания и последний известный статус.
- Приём и редактирование заявки передают в `details` имя, контакт, аудиторию, необязательную тему, `appointment` с датой и идентификатором специалиста и `expected_updated_at` из прочитанной записи. Приём выполняется с `action: "accept"`. Время назначается в форме заявки. Для новой встречи, у которой ещё нет слота, используется длительность 30 минут. Возврат после отмены восстанавливает последний статус и сохраняет время, если оно ещё доступно. История показывает прежние и новые значения изменённых полей.
- `GET /api/admin/requests/calendar.ics?status=confirmed` скачивает `text/calendar` с собственными записями сотрудника. В файл входят время начала и окончания в UTC и постоянный идентификатор события. Отменённые заявки и записи без времени пропускаются. Имена и контакты клиентов остаются в админке. Если событий нет, демо отвечает `404`.
- Если `registration_open=false`, форма консультации закрыта, список свободного времени пустой, `POST /api/requests` отвечает `409`. В интерфейсе настроек доступны приветствие и переключатель записи.

## Обратный звонок

Тело запроса содержит `phone`, `consent: true` и строковый `idempotency_key`. Фронтенд принимает десять цифр для номера с `+7` или полный номер с кодом страны. API получает одно значение с `+` и 10–15 цифрами, например `+79000000000`. Форматы для рабочего сайта нужно согласовать с НКО.

- Атомарно сохранить обращение и ключ идемпотентности. Первый успешный запрос возвращает `201`. Повтор с тем же ключом и номером возвращает тот же `id` и `200`. Тот же ключ с другим номером возвращает `409`.
- Настроить очередь или уведомление сотруднику, обработку заявки и доступ к контактам только из админки. Согласовать с НКО канал, сроки ответа, правила хранения номера и удаления данных. Номер не должен попадать в публичный ответ или обычные логи.
- Заглушка возвращает дополнительный флаг `demo: true`. Он включает сообщение о тестовом обращении. Рабочий API возвращает подтверждение после сохранения заявки.

## Локальная проверка

Из корня репозитория:

```sh
cd frontend
npm ci
npm run start:demo
```

Сайт открывается на `http://127.0.0.1:4200`, редактор — на `/admin/scenarios`. Демо-вход: `demo@kolibri.test` / `kolibri-demo`. API слушает `127.0.0.1:3077`. Данные остаются в `frontend/.demo-data/store.json` между перезапусками. Загруженные файлы хранятся в каталоге `frontend/.demo-data/media/`. В демо вводите только тестовые данные.

Проверка публикации: создайте тему и сценарий с заголовком, выбранной темой и одним шагом, сохраните черновик и убедитесь, что его нет в списке сайта. Нажмите «Опубликовать». Откройте список и саму инструкцию, затем снимите публикацию. Обе публичные ручки должны снова скрыть инструкцию.
